## Problem Statement

`agent-sweeper` cannot be used on a real machine. Every command reads `mock.Agents()` —
a hardcoded synthetic dataset (5 OpenCode / 4 Copilot / 4 Claude / 3 Codex / 2 Pi / 3
Cursor sessions with fabricated paths and IDs) — while the real stores on this host hold
1,241 OpenCode rows, 2,026 Codex sessions, and Pi 4. So `agent-sweeper stats` prints a
table (21 sessions, 280.8MiB) that matches nothing, `agent-sweeper sweep` dry-runs
fabricated sessions it can never actually delete, and active-session protection scans
real processes but matches them against fake IDs, protecting nothing. The deletion
engine (`internal/engine`) and protection (`internal/protect`) are real and tested, but
the seam between research (tickets 01–06) and that machinery was never bridged: **no code
reads a real session store into `[]model.Session`**. The map's destination — "detects the
six agents' local session stores, reports their footprint, cleans stale sessions" — is
unreached, and there is also no unattended interface to run a cleanup from cron or CI.

## Solution

- Build the **real session-store inventory adapter** — one seam that enumerates each of
  the six agents' actual on-disk session stores into `[]model.Session` (read-only) — and
  swap it in as the single source for `sweep` and `stats`. Mock data is demoted to a test
  fixture / `--demo` fallback only.
- Add a **non-interactive, scriptable** command path so the same sweep logic runs headless
  (`--agent`, `--age`, `--mode`, `--repo`/`--dir`, `--yes`), with machine-readable output,
  retaining every safety guarantee the interactive flow has.
- Restore interactive and scriptable flows to the real protection model: actively-open
  sessions are protected by matching **real** session IDs.
- Verify the whole pipeline against the real stores via the long-deferred field test —
  still without deleting anything.

## User Stories

1. As a user running `agent-sweeper stats`, I want the table to reflect my **real** session stores, showing true per-agent session counts, plan-based reclaim footprint, and store-row counts, so the numbers match a hand audit of the stores.
2. As a user, I want `stats` to read real, cross-platform data-root paths on macOS, Linux, and Windows (XDG, home-dotdirs, `%APPDATA%`), so it works on every machine where an agent has run.
3. As a user, I want `stats` to show me the plan-based reclaim footprint (remove-artifact bytes only), not raw store bytes, so DB-bulk that only a VACUUM frees is never counted as reclaimed.
4. As a user running `agent-sweeper sweep`, I want to pick from my **real** sessions (lists, not mock), grouped by directory or by git repo·branch.
5. As a user, I want the sweep dry-run to show my real per-session before-footprint, with protected sessions dimmed and the protection reason, so I can review exactly what would be deleted.
6. As a user, I want actively-open sessions detected against **real** IDs (process argv, Copilot locks, Claude roster, Cursor focus, grace window) to be protected and never shown as deletable.
7. As a user confirming a sweep, I want the engine to actually execute my real per-session deletion plans and reclaim exactly what the dry-run promised (dry-run==confirm), so nothing is deleted that wasn't reviewed.
8. As a user, I want a sweep to report real sessions that agree with a hand audit of the stores, so the difference from the old mock set is obvious.
9. As a user, I want `stats` to report a real, per-agent count of store rows a sweep would touch, without inventing any metadata.
10. As a user, I want `stats` to tell me how much disk a fully-real sweep would reclaim — without needing to run it.
11. As a user, I want deterministic, cross-platform reproducible output so I can trust the results are repeatable.
12. As a user, I want agents whose store is missing or empty reported honestly, so I can tell "not installed/missing" from "no sessions".
13. As a user, I want no real store opened for writing during detection or stats, so detection and dry-run never mutate my stores.
14. As a user, I want a scriptable path so I can run `agent-sweeper sweep --agent opencode --age 30d --yes` in cron/CI to clean stale sessions unattended.
15. As a user of scriptable mode, I want to filter by directory or repo·branch and pick an age via flags, matching the interactive pickers.
16. As a user of scriptable mode, I want `--yes` to be an explicit, mandatory confirmation so I can never sweep by accident.
17. As a user of scriptable mode, I want active sessions to remain protected even with `--yes`, so no flag can delete an open session.
18. As a user, I want scriptable mode to re-run protection scan at delete time (like the interactive confirm step) so nothing opened since the dry-run is swept.
19. As a user, I want scriptable mode output to be parseable (`--json`) or quiet (`--quiet`), so automation can read results.
20. As a user, I want scriptable mode to refuse with a clear error when protection revalidation finds nothing safe to delete, so I know why no sweep ran.
21. As a user, I want stats to support machine-readable output so my tooling can alert me.
22. As a user, I want a cleanup that respects the never-delete shared store list (OpenCode snapshot/, Cursor composer.content.*) so nothing shared is swept.
23. As a user, I want the plan to build per-session ordered actions (files first, record last: RemoveFile/RemoveTree/RemoveGlob/SQLDelete/DropJSONLLines/DropJSONKeys/StripKV) so an interrupted sweep leaves a self-healing ghost, not orphaned artifacts.
24. As a user, I want failed sweeps reported per-session and a re-run to converge.
25. As a user, I want VACUUM left to the user, but surfaced when a sweep deleted store rows, so SQLite file size isn't mistaken for reclaim.
26. As a consumer, I want a stable seam so a test or a downstream tool can feed a real-shape store tree and the whole pipeline works.

## Implementation Decisions

- **Architecture — the source seam.** A new `inventory` package is the single place that
  enumerates real stores into `[]model.Agent`. It is read-only, mirroring omnivue's
  registry-of-adapters shape (**not importing omnivue**). `inventory.Find()` returns the
  real agents; when a store is absent it yields the agent with `resolved: no store`.
- **Adapter registry.** Internal registry keyed by agent name (opencode, copilot,
  claude-code, codex, pi, cursor), registered from each adapter's `init()` with a default
  path — mirroring the omnivue registry pattern without importing it.
- **Mock demotion.** `internal/mock` is kept only as a test fixture and an explicit
  `--demo` fallback; both commands now default to the real seam.
- **Path resolution.** New path package resolving each agent's real data root
  cross-platform: OpenCode XDG (`$XDG_DATA_HOME/opencode` with home fallback);
  Copilot/Claude/Codex/Pi home-dotdirs honoring env overrides; Cursor splits its
  app-data store from `~/.cursor/projects` transcripts. Reuse the existing home-expansion
  logic for cases it already handles; extend it.
- **Per-agent real stores (read-only):**
  - **OpenCode:** session rows from opencode.db; cwd from records; last-activity =
    MAX(time_updated/time_created); enumerate per-session `storage/{message,part,session_diff}`
    artifact trees; no `snapshot/` enumeration.
  - **Copilot**: session-store.db rows + `session-state/<uuid>/` dirs; last-activity from
    updated_at; per-session `rewind-snapshots/` plus `events.jsonl`.
  - **Claude Code**: `projects/**/*.jsonl` transcripts (each a session); last-activity from
    mtime; cwd from project-slug + transcript.
  - **Codex**: date-partitioned `sessions/**/rollout-<ts>-<uuid>.jsonl`; last-activity from
    `session_index.jsonl` line or mtime; shell_snapshots.
  - **Pi**: `sessions/<cwd-slug>/<ts>_<uuid>.jsonl`, one file per session; last-activity =
    file mtime; no side artifacts.
  - **Cursor**: global state.vscdb KV rows keyed by `composerData:<id>`, plus
    `agent-transcripts/<uuid>/`; last-activity from lastUpdatedAt. Content-addressed blobs
    are never read as sessions.
- **Plan-based footprint + planner.** `engine.SessionReclaim` stays the shared seam; its
  input now comes from real plan accounting, not mock ratios. The inventory adapter builds a
  per-session ordered action plan (files→record, per decision 08 table) and sets
  `ReclaimBytes` to the sum of its remove-artifact bytes; `TouchesStore` set when the plan
  includes SQLDelete/StripKV. A planner turns a real session into its ordered action list so
  `engine.Execute` becomes reachable from commands, not tests only.
- **Wiring.** `sweep` and `stats` both call the seam; `protect` now matches real IDs. No new
  behavior in the engine package; `dry-run==confirm` stays.
- **Scriptable mode.** `sweep` grows `--agent`, `--mode dir|git`, `--dir`/`--repo`/`--branch
  filters, `--age <1d|3d|7d|30d|90d|1y|all>`, `--yes` (mandatory explicit confirmation).
  Non-interactive refuses without `--yes`; revalidates protection at delete time exactly
  like the interactive confirm; fails clearly if nothing is safe. Output human-readable,
  with `--json` and `--quiet`. `stats --json` added.
- **Safety invariants (unchanged, on real data).** No write during detect/stats; shared
  stores never in plans; no auto-VACUUM; `--yes` never bypasses protection; dry-run equals
  executed plan.

## Testing Decisions

- **The seam.** The one seam is the `inventory` package boundary: given a real-shaped
  fixture store tree, `inventory` yields the real `[]model.Agent`, and the existing
  `stats`, `sweep`, and engine slices run over it unchanged.
- **Good test** = exercises external behavior only: given a real-shaped store tree, the
  inventory yields the sessions/numbers you'd read by hand; a sweep/dry plan reclaims
  exactly those; protection spares open ones. No assertions on internal helper names.
- **`stats`** tested against a real-shaped tree rather than mock (prior art: current
  stats tests). **engine dry-run==confirm** stays intact. **inventory** adapters tested
  against a temp store root; missing store → `resolved: no store`. Prior art: omnivue
  adapter tests (not imported) + the existing fixture-safety guard.
- **Acceptance (field, ticket 14 payoff, still safe).** After wiring, run real
  `agent-sweeper stats` on the host against the known audit (1,241 OpenCode rows, 2,026
  Codex, etc.); a real `sweep` dry-run lists genuinely protected sessions and dims each
  with a reason (include a currently-open agent). **No confirm+delete** of live sessions —
  a human behind the confirm.

## Out of Scope

- Shared-store deep reclaim (OpenCode `snapshot/` git-gc; Cursor `composer.content.*`
  reference-counting) — excluded from per-session plans by 08.
- Config file to pin/exclude sessions (declined as a safety mechanism).
- Windows installer / winget / scoop.
- Session viewing / resume / search / UI server (a separate domain).
- Trash/restore — deletion is permanent by design.
